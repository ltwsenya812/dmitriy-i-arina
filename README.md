# Дмитрий & Арина · 31.07.2027

Свадебное веб-приглашение: конверт с печатью, замок, карета, двери во дворец, тайминг, дресс-код, детали, анкета гостя и обратный отсчёт.

Сайт — это один файл `index.html` и пара картинок в `img/`. Сервер не нужен.

```
index.html            приглашение целиком
admin.html            список гостей и счётчики (по паролю)
supabase/setup.sql    база для ответов гостей
tests/                автотесты (npm test)
img/kinder.webp       «Киндер» для экрана «Детали»
img/preview.jpg       картинка для превью ссылки в мессенджерах
apps-script/Code.gs   скрипт, который собирает ответы гостей в Google Таблицу
```

## 1. Хостинг на GitHub Pages (бесплатно)

1. Загрузите эту папку в репозиторий на GitHub (репозиторий должен быть **публичным**: на бесплатном тарифе Pages работает только для публичных).
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
3. Через 1–2 минуты сайт будет доступен по адресу `https://<ваш-логин>.github.io/<название-репозитория>/`.

Любое изменение, отправленное в `main`, само обновит сайт.

### Превью ссылки в мессенджерах

Telegram, WhatsApp и ВКонтакте показывают картинку `img/preview.jpg`, только если в `index.html` указан полный адрес. Когда сайт заработает, замените в `index.html` строку

```html
<meta property="og:image" content="img/preview.jpg">
```

на полный адрес, например `https://<логин>.github.io/<репозиторий>/img/preview.jpg`.

## 2. Подсчёт гостей: админ-страница + Supabase (бесплатно)

Ответы из анкеты сохраняются в бесплатной базе Supabase, а смотреть их удобно на странице **`admin.html`** этого же сайта: вход по паролю, счётчики «Придут / Не смогут / Всего», напитки, поиск, фильтр, удаление тестовых ответов и выгрузка в CSV. Если гость отправит анкету второй раз с тем же именем, его ответ обновится, а не задвоится.

1. Зарегистрируйтесь на supabase.com (можно через GitHub) и создайте проект: **New project**, регион — ближайший (например, Frankfurt). Пароль базы сохраните у себя.
2. В проекте откройте **SQL Editor → New query**, вставьте содержимое `supabase/setup.sql`, **в последних строках замените `ПРИДУМАЙТЕ_ПАРОЛЬ` на свой пароль для админки** и нажмите **Run**.
3. Откройте **Project Settings → API** (или **Connect**) и скопируйте **Project URL** (`https://xxxx.supabase.co`) и публичный ключ **anon / publishable** (не `service_role` и не secret!).
4. В `index.html` найдите строку `var RSVP_URL='';` и впишите:

   ```js
   var RSVP_URL='https://xxxx.supabase.co/rest/v1/rpc/submit_rsvp?apikey=ПУБЛИЧНЫЙ_КЛЮЧ';
   ```

5. Сохраните изменение в репозитории. Через минуту откройте `…/admin.html`, введите пароль из шага 2 и отправьте тестовый ответ из анкеты — он появится в списке (тестовый ответ можно удалить крестиком).

Публичный ключ можно хранить в открытом коде: без пароля по нему можно только отправить ответ анкеты, читать список нельзя.

**Важно:** пока `RSVP_URL` пустой, анкета показывает гостю «Спасибо!», но ответ никуда не уходит.

Папка `apps-script/` — запасной вариант с Google Таблицей, если он когда-нибудь понадобится.

## 3. Тесты

Автотесты на Playwright проверяют приглашение на телефоне и компьютере: открытие конверта, тексты, «Вы» с большой буквы, что имена не переносятся и ничего не вылезает за край, двери и тайминг при прокрутке, анкету (ответы в тестах уходят в подменённую базу, настоящая не трогается), обратный отсчёт, «Киндеры», режим без анимаций и админ-страницу. Отдельный тест следит за плавностью: на замедленном вдвое процессоре экран с замком должен держать больше 35 кадров в секунду без подвисаний.

```bash
npm install
npx playwright install chromium   # один раз
npm test                          # все тесты
npm run perf                      # подробный замер плавности по экранам
```

## Что поменять перед рассылкой

- Срок ответа на анкету («до 1 июня 2027») — в разделе `rsvp` в `index.html`.
- Подпись к кнопке карты и адрес — в разделе `hall`.
- Время для обратного отсчёта — строка `new Date('2027-07-31T16:30:00+03:00')`.
